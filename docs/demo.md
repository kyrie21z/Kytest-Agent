# A0 / A4 操作与一分钟演示

## 1. 启动

在解压后的 `code-agent/` 目录运行，推荐 Linux/WSL、Python ≥3.9。
命令执行默认需要 Bubblewrap，Ubuntu 可用 `sudo apt install bubblewrap` 安装。

```bash
python -m venv ~/.venvs/kytest-agent-homework
source ~/.venvs/kytest-agent-homework/bin/activate
python -m pip install -r requirements.txt
python web.py
```

打开 **http://127.0.0.1:8765**。虚拟环境放在 Linux 文件系统、路径不含空格。
端口占用时运行 `python web.py --port 0`，打开终端打印的地址。按 Ctrl-C 结束服务。
真实模型在项目 `.env` 配置 API Key、兼容地址、模型名，再重启；凭据只留在服务端。

## 2. 先看架构，再运行对比

1. **查看架构图与机制卡片。** A0 使用通用提示与工具，自主写测试、运行命令；A4 增加
   测试生成提示、`submit_tests` 与完成钩子，逐条检查候选、合并接受项并回归。
2. **展示共同输入。** 载入区间分类示例，查看源码和任务；选择真实或脚本模式。
3. **点击“同一输入对比 A0 / A4”。** 服务冻结这份源码、任务和配置，同时启动
   A0、A4，各用独立工作区。两组均受相同生成预算限制，内部验证计入 A4 成本。
4. **核对两列证据。** 大数字卡片显示轮次、工具调用、token总量与输入/输出分项。
   执行过程按轮次显示模型公开说明、工具参数、返回结果和耗时；取消“跟随最新”可检查历史。
   切换“质量评价”查看共同pytest复验、语句/分支覆盖率、固定故障检出及存活项。
   展开 A4 候选，可见原始契约引用、输入域、预期值解释、故障假设以及验证记录。
   下载两组测试或 A4 报告；点击“返回输入”可继续单独运行任一策略。

脚本模式中两组最终测试相同。A4 刻意提交一个错误边界预期和一个不存在的契约引用，
真实验证器分别记录 `FAIL`、`REJECTED`；修正后合并为五项通过的测试。
这是**机制演示**，不比较模型能力。真实模式分别请求同一模型，费用按两次运行计算。

A0 也能自行执行 pytest；Web 的最终复验对两组相同。A4 的候选接受不保证复杂
预期值正确，更不能证明缺陷检出率更高。正式成绩仍以独立实验为准。
停止对比会取消两组后续动作，等待当前请求或工具结束；刷新页面恢复最近一次对比。

## 3. 评价口径

测试有效性要求实际执行且通过、目标源码保持原样；全部跳过不算有效测试。
语句与分支覆盖率使用coverage独立副本测量。固定故障集仅适用于内置classify：
上下边界各一个错误、区间下方/上方/内部各一个返回值错误，共5个，均有契约见证。
只将确认失败的有效故障计为检出；超时、环境错误和未完成项保留，不冒充检出。
自定义源码没有此固定故障集，显示“未配置”；缺失指标显示未测量，不记为0。

生成完成后，两组采用同一评价方法；评价结果不回灌模型，生成时间与评价时间分列。
总耗时包含生成、最终复验和质量测量。token按服务响应usage累计，缓存包含在输入中；
服务未报告用量时明确显示，脚本模式显示无模型用量。并行耗时也受共享资源与服务负载影响。

## 4. 不超过一分钟的录制流程

| 视频时段 | 操作 | 展示内容 |
|---|---|---|
| 0–8 秒 | 查看卡片和共同输入 | A0 自主流程；A4 候选验证流程 |
| 8–20 秒 | 点击同一输入对比 | 两组同时启动，观察各自消息与工具调用 |
| 20–40 秒 | 查看并展开 A4 拒绝记录 | 错误预期、无效引用与修正后的候选 |
| 40–55 秒 | 展示共同复验与下载 | 两组最终文件真实执行，下载测试与报告 |

录制时保留模型模式标记，不打开 `.env`。真实服务耗时不固定；加速或剪掉等待须标注。
