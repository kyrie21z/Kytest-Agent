# 评价：有效性、判别力与成本

测试通过说明它与参考实现一致，覆盖率说明它执行了哪些路径，故障检出说明断言能否区分给定错误。三者分别测量，模型的完成声明不能替代实际执行。

## 主要对照

MBPP 20 题，每种配置生成 3 次。通用生成、契约验证和可选开发故障反馈共 180 次运行。任务、顺序与配置在请求前冻结，条件交错派发；先对每题的三次结果取均值，再对 20 个任务等权比较。

| 指标 | 通用生成（A0） | 契约验证（A4） |
|---|---:|---:|
| 有效产出 | 49/60 | 59/60 |
| 确认独立故障检出率 | 68.81% | 74.94% |
| 平均返回 token | 20,688 | 21,827 |
| 平均生成耗时 | 45.1 秒 | 53.0 秒 |

契约验证的观测差为 **+6.13 个百分点**，95% 任务 bootstrap 区间 **[−5.12, +17.26]**，Holm p=0.7466。总体质量优势未通过预设验收，因此通用生成保持默认，契约验证按需启用。

可选开发反馈（A5）的有效产出为 59/60，独立检出率 74.90%，未显示平均质量优势。统计复核保留其全部记录与预设比较，避免改变比较家族；完整实验矩阵见[固定档案](https://github.com/kyrie21z/Kytest-Agent/blob/development-archive-20261008/submission/EXPERIMENTS.md)。

## 计量口径

- **有效产出**：pytest 实际通过且目标源码未被改写；无测试、全部跳过和执行失败不算有效。
- **主分数**：无效产出计 0；有效套件的确认检出数除以固定故障总数。超时和疑似等价项保留分母，不算确认检出。
- **独立故障池**：比较、逻辑连接与布尔常数替换。开发反馈使用算术与常数替换，按 AST 指纹核对两池无交集。
- **成本**：token 为服务返回的 input + output 用量，生成耗时不含最终评价；系统验证与测量成本另记。

各条件使用 qwen3.7-flash、temperature=0.2、12 轮、每请求最多 4096 输出 token。累计 30000 token 与 300 秒在轮次边界检查，是软上限，不能解释为严格等成本。

## 可复核证据

[`evidence/`](evidence/)只保留 180 行派生数据、统计期望与来源哈希。以下命令检查任务成员、重复次数、固定分母、均值、bootstrap、Wilcoxon 与 Holm：

```bash
python scripts/verify_evaluation.py
```

成功输出 `all_matches: true`。它复核既有数据的统计，不重新请求模型，也不重放全部被测程序。原始运行、冻结源码、协议和独立重放记录保存在[开发档案标签](https://github.com/kyrie21z/Kytest-Agent/tree/development-archive-20261008)。CSV 中的原始记录路径相对于该档案，字节哈希保持不变。

## 结论的边界

完整独立重放中，冻结主分数 180/180 一致，参考与变异状态 179/180 一致，严格状态验收未通过。一份随机大列表测试暴露上游参考排序缺陷，原始失败与 0 分保留。因此有效产出率表示参考一致性，不能当作预期值正确率。

展示案例经过筛选，不能证明总体收益。公开基准的模型预训练接触未知，函数级样本也不能外推真实仓库的缺陷发现能力；置信区间包含 0 不代表两种路径等价。工程测试与离线演示验证机制，真实模型质量由上述对照单独评价。
