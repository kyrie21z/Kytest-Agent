# A4 开发试验协议（运行前冻结，2026-10-06）

目的：检验“契约依据 + 逐测试验证 + 增量保留”是否改善测试有效性和故障检测能力。
这是开发试验，不是最终评测。A0–A3 的历史结果保持独立，不能与本次新采样混合。

1. 输入仅使用既有 `benchmarks/smoke_pool_5.jsonl` 的五例
   HumanEval/1、122、154、4、69。v2 的20例不参与开发调参或模型调用。
2. 条件 A0 和 A4，各实例独立重复3次，共30个run。调用本地已配置模型，
   相同 temperature=0.2、12 turns、每请求输出4096、累计30000 input+output token。
   累计token在请求间检查，单次请求可超出剩余额度，实际超出如实报告。
   最大30×12次模型调用（每调用至多1次网络重试）。不假定服务支持固定采样seed。
3. 每run生成阶段300秒，工具命令单次上限10秒；A4候选单条2秒、合并回归5秒，
   总候选尝试24次、每提交至多6条。生成时钟在turn间检查，不是强制精确抢占。
   各条件生成完成后才采集pytest/coverage/mutation，测量时间不挤占生成预算。
   并发2，任务次序以seed=20261006固定打乱；重复标签不是模型随机种子。
   测量上限两条件相同：pytest 3秒、coverage run 10秒、每变异体3秒。
4. 主开发指标为有效杀伤率：正确实现上all_pass才计实际mutation score，否则0。
   同时保留原始杀伤率、all_pass、timeout、token、生成/测量时间、A4逐条拒绝原因。
   所有启动run均计入。零变异体实例不进杀伤率均值并明确报告。
   使用原引擎的固定前20个变异体，上限及等价变异体问题不在看到结果后修改。
   这些评分变异体不进入Agent上下文或工具反馈；本阶段不做mutation-guided补测。
5. 先在同一实例内平均3次，再算五个实例的A4−A0差值。报告均值、实例差值、
   重复波动及成本；五个开发实例不足以证明总体收益。不得按run挑选最好结果。
   只有有效性不下降且平均有效杀伤率上升，才把该机制列为进入独立评测的候选；
   仍需独立评测确认，开发试验上升不等于最终优势。

候选必须记录docstring原文依据、输入域、独立oracle推导和具体故障假设。
可机械识别的字面量调用按显式数值/长度范围、正整数和非空前提检查；
未知表达式/未识别自然语言约束保持“未检查”，不声称证明契约正确。
参考实现执行只能证明兼容性。保留通过的测试，以独立执行定位错误和超时，
再以合并回归检查防止新候选破坏已有测试。元数据是可审核的模型陈述。

执行前 `scripts/run_testgen_pilot.py` 保存协议、代码、数据SHA-256、配置摘要和
完整任务次序manifest；协议/输入/代码变化后不能续跑同一目录。绝不写入API Key。
