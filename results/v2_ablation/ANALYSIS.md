## 5. 机制取证（system_actions 落盘数据）

**A2（执行反馈）**：20/20 实例触发钩子；系统 pytest 共 32 次，
其中 12 次失败→注入修复请求→模型修复；19 次通过→收尾。
0 次 solution.py 恢复，0 次联网尝试。修复闭环真实发生：
12 次失败反馈全部来自"模型写了跑不过的测试"，是确定性编排
在替代模型的"自觉"。

**A3（覆盖率反馈）**：覆盖率分析在 18/20 实例上触发并全部给出
定向反馈（未覆盖行区间）；但 0 次达到全覆盖收尾，0 次
tests_passed 收尾——补测轮次要么被 pytest 上限（4 次）截断，
要么模型重写文件后未再通过。A3 杀伤率反而低于 A2（66.6% vs 70.6%）：
覆盖率定向补测**没有转化为杀伤率**，且全文件重写有丢弃原有强测试的
风险。这是 RQ3（覆盖↑ ⇔ 抓 bug↑？）的又一条否定性证据，
与仪器校准阶段"覆盖率分不出弱断言与空测试"的结论互洽。

## 6. 失败分析

**状态分布**：A0 {all_pass 19, timeout 1}；A1 {all_pass 17, max_turns 1, timeout 2}；
A2 {all_pass 19, timeout 1}；A3 {all_pass 18, timeout 2}。

**6 例 timeout 的共同签名**：turns=2、tools=2、has_tests=True、
line_coverage=0%、duration 800–1500s。即 Agent 本体在 2 轮内完成
（读 + 写），超时发生在评测子进程（coverage/变异）高并发慢化阶段，
而不是 Agent 卡死。按 ITT 原则按实际测量计分。运行环境因素：
并发 6 + 每实例 20 个变异体 × pytest 的评测负载是主因。
HumanEval/44 在 3/4 变体上超时（A2 上通过且杀伤率 0.83，四变体最高），
属系统性难例与负载波动的叠加。

**记录中的联网迹象和 solution.py 改写计数均为0**；
目录分离与迹象计数不能证明历史运行具有文件或网络隔离。

## 7. 对研究问题的回答

- **RQ1（通用 Agent 能做多好）**：A0 在难例集上杀伤率 70.4%，
  与官方测试（69.4%）持平——通用 Agent 的自发性在这个量级上
  已接近人类参考套件，提升空间在尾部实例。
- **RQ2（各机制贡献）**：测试感知提示（A1）在本次实验中零贡献且增加成本；
  执行反馈（A2）质量未检出差异、token −56.43%；该观察只涉及历史记录中的
  token 效率，未证明等价或实际费用差；覆盖率反馈（A3）未显示增量。
- **RQ3（覆盖↑ = 抓 bug↑？）**：否定。A3 在覆盖率反馈触发 18 次、
  模型确实补测的情况下，杀伤率不升反降（配对 −4.0% [−13.7%, +3.3%]）。
  与校准实验互为印证：覆盖率测量的是"执行到"，不是"检查对"。

## 8. Threats to Validity

1. **样本量分辨率**：n=20 配对设计检出下限约 0.5 SD；小于 9 个百分点的
   真实效应无法与噪声区分。A2 的 +1.2% 可能掩盖了真实的小幅改善。
2. **评测集构建**：v2 按 A0 筛查难度富集，选集先于 A1–A3 运行且 A0 全新
   重跑，规避了均值回归；但富集本身使绝对数字不可与自然分布直接比较。
3. **并发负载污染**：6 例 timeout 与评测子进程负载相关，可能对
   不同变体造成不均匀的测量噪声（timeout 实例的覆盖率均为 0）。
4. **A3 的上限截断**：pytest 上限 4 次使部分实例的覆盖率阶段未完全
   展开（18 次反馈后 0 次收尾）；A3 的真实潜力可能被低估。
5. **单次运行**：每实例每变体 1 次（temperature 0.2），未做重复测量；
   配对设计吸收部分噪声，但逐实例的采样波动仍在。
