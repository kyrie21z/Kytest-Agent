# 独立故障反馈协议（A5，实验功能）

当前v2会自动调用开发检查并控制继续/停止，记录新增检出与剩余目标；详细语义
见 [testgen-quality-v2.md](testgen-quality-v2.md)。以下故障家族划分继续有效。

冻结于本闭环演示运行前。A4 的 30-run 开发试验没有使用此工具，不能作为 A5 证据。

1. 开发反馈限定 AOR（算术）、CRP（常数）两类，最多8个候选。
   独立评分限定 ROR（比较）、LCR（逻辑连接）、BCR（布尔常数），最多20个。
   两池按 AST 指纹检查无交集。RVR 返回改写可能与常量或布尔改写完全相同，
   本协议不使用它。相同源码、不同候选编号不能算独立。
2. `inspect_survivors` 只能读取 `submit_tests` 私有接受的套件，先确认原实现通过，
   再在隔离子进程执行开发候选。向 Agent 提供未检出的改动位置、差异与描述，
   至多两轮已改变套件的反馈；重复查询复用缓存。超时/执行故障不算检出。
3. Agent 根据契约补充有效域内的断言，并覆盖相邻边界；全部新增测试仍须经过
   逐条验证与合并回归。疑似等价候选保持不确定，不能为杀它添加无效输入要求。
4. 最终评分在生成结束后进行，评分源代码、编号和结果不进入 Agent 反馈。
   A5单例runner强制评分家族；手动比较基线须用相同 `mutation_operators`。
   包含A5的批量runner自动统一全部条件的评分家族，并拒绝续用旧评分池记录。
   A5 分数不可直接与历史全家族 A0–A4 分数比较，也不代表所有故障类型。

演示先提交一条区间内部测试，再从开发反馈定向添加区间外部与两端包含边界。
在 Agent 结束后，分别用同一独立评分池测量补测前后的套件。演示采用脚本化
LLM、真实 Agent/沙箱/pytest；只验证反馈通道及跨家族检测能力，不证明真实模型
平均质量提升。评分池可能包含有效域等价变异体；存活不自动意味着遗漏真实故障。

```bash
python scripts/demo_fault_feedback.py --output /tmp/kytest-fault-demo
python main.py -C /path/to/target --fault-feedback --print "为 solution.py 生成测试"
```

输出目录必须新建。CLI 第二条依赖已安装 pytest 与可用沙箱；未配置模型时普通
Mock 不保证遵循新工具协议，验收演示使用第一条。普通 Agent 默认工具集不变。
